# 架构与性能

## 资源归属

主窗口拥有唯一的托盘图标、设置菜单、硬件采样器、桌面观察器和网卡目录。副屏窗口只负责定位、显示与拖动，不创建隐藏的托盘图标、菜单树或独立轮询循环。

所有面板共用一个 120 ms UI 调度器，以保留任务栏自动隐藏的响应速度。它不以相同频率读取注册表或全局扫描窗口。

## 菜单

菜单复用现有控件树，在设置、显示器、任务栏句柄或网卡列表版本变化时才重建。重建期间暂停布局，最后统一完成布局，避免添加每个菜单项和设置 Padding 时重复测量全部菜单。

菜单路径不枚举网卡或全局查找副屏任务栏。网卡目录由后台更新；桌面状态提供已缓存的任务栏句柄。`StartupManager` 在后台通过 Task Scheduler COM 读取开机启动状态，菜单只读取缓存，避免系统服务冷启动阻塞右键菜单。

## 管理员开机启动

`StartupRegistration` 独立生成 Task Scheduler XML，绑定当前用户 SID、交互式登录、最高权限、10 秒延迟及不限时运行。设置任务成功并核对配置后才移除旧 Run 项。关闭时删除当前用户专属任务和旧项；不停止当前应用实例。

普通权限修改由同一程序的管理员辅助模式完成，校验账户 SID 一致；启用成功后可以运行新任务，让普通实例退出后由最高权限实例接手。辅助命令在单实例锁之前处理，登录启动会等待旧实例交接。Task Scheduler COM 对象按连接范围释放，不增加常驻服务，不保存密码，不修改 UAC 设置。

## 桌面状态

`DesktopState` 使用 WinEvent 和显示设置事件标记快照失效；回调只设置标志，不在回调里遍历窗口。UI 线程合并事件后统一捕获一次窗口列表，供所有屏幕判断遮挡和全屏。保留约 1.5 秒兜底检查；无法安装事件钩子时采用较快轮询。

任务栏实际位置和可见状态仍定期读取，因此自动隐藏不必等待完整桌面快照。缺少副屏任务栏时，不逐帧触发全局重新枚举。主题在设置通知或较慢的兜底周期读取，避免每块屏每帧打开注册表。

## 采样与绘制

`Sampler` 在单个后台工作循环读取 CPU / GPU / 温度 / 风扇与网络统计。`NetworkInventory` 缓存网卡对象和名称、类型、连接状态，网络事件会触发后台刷新，正常情况下约 5 秒更新目录；每次硬件采样仍读取活动接口的即时累计字节，速率基于实际间隔。

后台仅替换“最新采样”，UI 取走该值后更新所有面板。UI 繁忙时不会堆积 BeginInvoke 刷新。隐藏面板不创建绘制位图，显示内容未变化时也不重复提交图层。窗口位置和 Z 序仅在几何或桌面状态变化时更新。

进程权限结果在启动后缓存，查询使用的 WindowsIdentity 立即释放；关闭主窗口时解除静态系统 / 网络事件及 WinEvent 钩子，关闭副屏并释放自有字体和托盘资源。

## 检查边界

`--self-test-layout` 验证合成的全屏、遮挡与显示器选择场景。`--verify-displays` 检查当前显示器与实际面板；`--verify-menu` 是会短暂打开菜单的交互检查，用户在期间点击外部可能关闭菜单，不宜作为安装成功的唯一判断。

`--benchmark-ui` 在独立测试进程中临时选择所有显示器，先观察约 6 秒常规运行，再执行菜单准备与缓存检查。CPU 的观察区间不含后面的菜单检查；调用计数包含初始化、观察与菜单准备阶段。其菜单准备耗时不包含 Windows 动画或鼠标输入到像素显示的完整延迟。短时 CPU / 内存结果受启动、JIT 和其他程序影响，不能直接当作长期占用承诺。
